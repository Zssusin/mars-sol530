# 把 C++ 版接进 Godot 项目（fedora，开机后做）

**原则**：
- 装了扩展（`ClassDB.class_exists("MarsTerrainCore")`）就走 C++；
- 没装、或者加 `--C++=0`，就走原来的 GDScript；
- 两条路结果逐位相同（见 `tests/parity`），所以随时可以切回去对照。

## 0. 编译、放置

整个 `仿真核心/` 放到 `地图/godot/扩展/仿真核心/`（= `res://扩展/仿真核心/`），同步时排除 `._*`：

```
rsync -a --exclude '._*' 仿真核心/ fedora:"~/Documents/mars-work/地图/godot/扩展/仿真核心/"
cd 地图/godot/扩展/仿真核心/gdextension
git clone --depth 1 https://github.com/godotengine/godot-cpp
scons platform=linux target=template_debug api_version=4.7 -j12      # → 仿真核心/bin/libmars_sim.linux.template_debug.x86_64.so
scons platform=linux target=template_release api_version=4.7 -j12    # → 仿真核心/bin/libmars_sim.linux.template_release.x86_64.so
```

**目录约定**：
- `mars_sim.gdextension` 在 `仿真核心/` 根下，库在 `仿真核心/bin/`，两者路径已经对上（原来 SConstruct 输出到 `gdextension/bin/`，扩展会静默加载失败，已修）。
- `gdextension/`、`core/`、`tests/` 里各有一个 `.gdignore`：编辑器不扫 godot-cpp 源码，也不会把 `tests/parity/原版/` 里的旧脚本当成项目脚本（会和正式脚本的 class_name 冲突）。
- 装好后启动应打印"[实景] 地形取高、选块、撒石：C++"；没打印就是没加载上。

先在 fedora 上跑一遍对拍：`tests/parity/run.sh <实际要用的 Godot 二进制>`，要求全部逐位一致。打了引擎补丁就对**自编引擎**跑，不是官方版。

这一步是必须的。Mac 上的对拍是 arm64 + Apple libm；fedora 是 x86-64 + glibc，两边各自要和本机 Godot 一致。

## 1. 地形LOD.gd

```gdscript
var core: RefCounted = null                     # C++ 版（MarsTerrainCore）；null = 走下面的 GDScript

# setup() 末尾加：
	if ClassDB.class_exists("MarsTerrainCore") and args.get("C++", "1") == "1":
		core = ClassDB.instantiate("MarsTerrainCore"); core.configure_heights(self)
		core.set_threads(int(args.get("C++线程", "0")))   # 0 = 默认（硬件线程一半，最多 8）；1 = 单线程，结果逐位相同
		print("[实景] 地形取高、选块、撒石：C++")

# h_cpu、h_data 开头各加一行：
	if core: return core.h_cpu(x, z, kmin)      # h_data 里换成 core.h_data(x, z, kmin)

# update() 里把"var out := [] … sel(…)"那段换成：
	var out := []
	if core:
		var P: PackedFloat64Array = core.select(cam, pixel_angle)
		for q in range(0, P.size(), 6):
			out.append([int(P[q]), P[q + 1], P[q + 2], [P[q + 3], P[q + 4]], int(P[q + 5])])
	else:
		…（原来的两层循环）
```

`range0`、`R` 和材质参数的设置留在原处：C++ 用同样的公式算，结果一致。

## 2. 实景.gd

```gdscript
# build_ground()：geo 建好、lod.geo = geo 之后
	if lod and lod.core: lod.core.configure_geo(geo)      # geo 为 null（--地貌=0 时仍有对象，on = 0）也可以传

# build_rocks()：scat.setup(…) 之后
	if lod and lod.core and scat: lod.core.configure_scatter(scat)

# rock_bucket() 开头：
	if lod and lod.core:                                   # 固定石块分级 + 撒石收集，一次在 C++ 里做完
		var fixed := []
		for T in rk_types: fixed.append({"pos": T["pos"], "D": T["D"], "buf": T["buf"]})
		var res: Array = lod.core.rock_bucket(cam, pa, budget_ms, fixed)
		if scat:
			var st: Dictionary = lod.core.get_scatter_stats()
			scat.pending = st["pending"]; scat.n_tiles = st["tiles"]; scat.n_rocks = st["rocks"]; scat.n_band = st["band"]; scat.n_lv = st["level"]

```

**其他模块不用改**：控制、声音、天气这些用到 `lod.h_cpu` 的地方，自动就走 C++ 了。

## 3. 车辆物理（可选，接控制模块时）

`step` 每步约 0.4 ms（Mac），可以直接放 `_physics_process`。取高网格 200×200 要约 15 ms，**放后台线程算**：

```gdscript
var sim := MarsRoverSim.new(); sim.set_soil("M90")
var grid_task := -1

func _regrid(x0: float, z0: float) -> void:          # 车周围 10 m、5 cm
	var h := lod.core.h_cpu_grid(x0, z0, 0.05, 200, 200)
	sim.call_deferred("set_height_grid", h, 200, 200, x0, z0, 0.05)

func _physics_process(dt):
	var s: Dictionary = sim.step(dt, wheel_omega, yaw_rate)   # ω < 0 倒车
	if (s.off_grid or 离网格边 < 3 m) and grid_task < 0:      # 车快走出网格：后台重算
		grid_task = WorkerThreadPool.add_task(_regrid.bind(新x0, 新z0))
	if grid_task >= 0 and WorkerThreadPool.is_task_completed(grid_task):
		WorkerThreadPool.wait_for_task_completion(grid_task); grid_task = -1
```

状态里新增：`skidding`（下坡最大制动也刹不住，准静态模型给不出加速度，只提示）、`off_grid`（本步取高出了网格）、`slip_evaluations`（诊断）。

## 4. 验收

1. 对拍全部逐位一致（fedora）。
2. `--C++=0` 和 `--C++=1` 各出一套四机位图：逐像素相同。实例顺序可能不同，但不影响画面。
3. `测帧.sh` 四个场景：GPU 时间不变；`--C++线程=1` 和默认各跑一遍，CPU 端看：
   - 撒石 `pending` 消失：不再需要分好几帧才收完；
   - 快速飞行时远处石块换级的滞后变小。
4. 照片回归不变。

## 地平线 GI（2026-10-07）

`core/horizon.{h,cpp}`、`core/rock_occlusion.{h,cpp}` + `MarsTerrainCore` 五个方法，GDScript 侧是 `godot/地平线GI.gd`（默认开，`--地平线GI=0` 关）：

| 方法 | 何时调 | 耗时（fedora 16 线程） |
|---|---|---|
| `horizon_maps(stride=2, dirs=16, growth=0.1, t_max=40000)` | 加载时一次（`configure_heights`、`configure_geo` 之后），结果缓存到盘 | 15 层约 2.9 s |
| `horizon_sky_table(rgb, w, h, scale, dirs, nb)` | 换天空时 | 约 25 ms |
| `horizon_irradiance(maps, table, dirs, nb, half=false)` | 换天空时，接在上一个后面；`half = true` 出半精度（地平线GI.gd 用这个） | 约 70 ms |
| `horizon_sun(stride=2, azimuth=0, growth=0.1, t_max=40000)` | G2 远处地影：太阳方位变了 > 0.25° 时（仰角在着色器里比，不用重算）；返回 Array[L] 个 PackedFloat32Array（太阳方位上的地平线仰角，弧度） | 第一次约 0.53 s（含建高度网格）；之后约 0.12 s（实景，fedora）。实时档在后台线程算 |

| `rock_occlusion(res, types, x0, z0, cell, n)` | G4 石块遮地面：石块分级更新后（后台线程）；`res` = `rock_bucket` 的结果，`types` = 每种单位网格的包围盒（6 个数）；返回 n×n L8 可见度 | 2048² 一级约 10–14 ms |

高度网格（每层 601² 的 `h_cpu`）在扩展里只建一次，`horizon_maps` 和 `horizon_sun` 共用；`configure_heights` / `configure_geo` 时清掉。

设计与结果见 `资料/实时引擎/地形GI设计.md` §9。
