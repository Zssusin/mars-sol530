# 仿真核心：火星车辆物理（C++ GDExtension，2026-10-06 v0）

在 Mac 上写好，并在 Mac 上测过核心部分。开机后同步到 fedora 的 `地图/godot/扩展/仿真核心/`。

## 做什么

| 部分 | 内容 |
|---|---|
| 轮–土力学 `core/mars_terramechanics.*` | 刚性轮，Bekker 压力–沉陷 + Wong–Reece 应力分布 + Janosi–Hanamoto 剪切。输入轮载和滑转率，给出沉陷、净牵引力、驱动力矩。多个轮子共用一个滑转率时，解出能提供所需总牵引力的滑转率；提供不了就判陷车 |
| 摇臂–转向架 `core/rocker_bogie.*` | 六轮车在任意高度场上的准静态仿真：用牛顿法解车体高度、俯仰、侧倾、差速器转角、左右转向架转角，让 6 个轮子都着地（轮子能骑上石块边缘）；静力分配各轮载荷；再用轮–土力学算滑转、沉陷、车速、功率 |
| 地形与撒石的 C++ 版 `core/terrain_core.*`、`core/scatter_core.*`、`core/godot_compat.h` | 把 GDScript 的 CPU 热点逐行移植过来：地形取高 `h_data` / `h_cpu`、地貌印章镜像（坑、沙纹、地类、分辨率）、CDLOD 选块和包围盒、撒石区块生成、可见区块收集、逐块分级、固定石块分级。**和原 GDScript 逐位一致**（见下面的对拍） |
| GDExtension `gdextension/` | `MarsRoverSim`（车辆物理）、`MarsTerrainCore`（地形与撒石），供 GDScript 调用。接入方法见 `接入.md`：装了扩展走 C++，没装照旧走 GDScript |

核心是纯 C++17，不依赖 Godot，方便单测，以后 RTS 的车辆也用它。

## 多线程（2026-10-06）

`core/thread_pool.h`：常驻工作线程 + 调用线程一起做 `parallel_for`，纯 C++17。`MarsTerrainCore` 第一次用时才建池，默认线程数 = 硬件线程数的一半（最多 8），`set_threads(n)` 可改，`1` = 单线程。

**撒石收集**（`Scatter::collect`）拆成四步，输出的内容和**顺序**都与单线程逐位相同：
1. 缺的区块并行生成（`gen_tile` 是 const、只读地形）；
2. 并行给每块石头定级，记下各区块每类每级的块数；
3. 串行按区块顺序排出每个区块在输出里的起点（= 单线程逐个追加时的位置）；
4. 并行按起点写入，各区块写各自的区间。

| | 单线程 | 多线程（Mac 10 线程） |
|---|---|---|
| 冷缓存（3 机位，31.7 万块） | 216 ms | 38 ms（5.6×；4 线程 70 ms） |
| 热缓存（每帧常见情况，每机位） | 2.0 ms | 0.65 ms |

`h_cpu_grid` 按行并行；线程池正被 `rock_bucket` 占着时不等，在本线程串行算。

**检查**：
- `parity_dump` 每次都跑单线程和多线程两遍，逐字节比较（内容 + 顺序 + 统计），再把多线程的结果交给 GDScript 对拍：全部逐位一致；
- ThreadSanitizer 下 2、3、7 线程无竞争报告；
- 单元测试：每个任务恰好做一次、嵌套调用不死锁、换线程数。

**没并行的**：CDLOD 选块（每机位约 1.2 ms，要写包围盒缓存，并行要加锁，收益小）；车辆物理（每轮一次只要几 µs，开线程不划算）。

**踩到的坑**：第一次对拍有 1 个点的沙纹高度差 1 ulp。原因是 C++ 编译器把 `pow(sin(…), 2)` 优化成了 `x*x`，而 GDScript 在运行时调用的是 libm 的 `pow`。改成所有 libm 函数都经 volatile 函数指针调用以后，全部一致。

**这些规则必须遵守**（写在 `godot_compat.h`）：
- 编译加 `-ffp-contract=off`；
- Vector2、Vector3、Basis、Color 按 float 算；
- 随机数是 Godot 的 PCG32，randf、randfn 用 float 版。

**速度提升影响什么**：
- 影响的是 CPU 端的卡顿和滞后：撒石不必再分好几帧才收完，远处石块换级不再慢半拍；同时给以后的 RTS 模拟腾出 CPU；
- 不影响 GPU 帧时间：现在每帧主要是 GPU 在忙。

## 车辆物理的速度（2026-10-06 改）

原实现每步 75–82 ms，放不进 60 Hz。原因是三层求解嵌套、每层都重复算：

| 层 | 原来 | 现在 |
|---|---|---|
| 滑转率（6 轮共用） | 二分 40 次 + 两端 = 42 次总牵引力 | Brent 法，从上一步的解热启动：约 5 次 |
| × 每轮沉陷 | 二分约 30 次 + 首尾 = 32 次积分 | Brent 法，从该轮上一次的 θ1 热启动：约 4–6 次 |
| 每次积分 | 3 个 Simpson × 161 点，每点 σ 算 5 遍、τ 算 3 遍（约 20 次 libm） | 3 个积分一遍算完，每点 σ、τ 各算一次（约 5 次 libm） |

结果：Mac 上每步 0.12–0.48 ms（约 170 倍），滑转率、沉陷与原实现差 < 1e-6。

同时修正：
- **倒车**：原来不管 ω 正负都按车头方向算坡度（车头朝上坡倒车被当成爬坡，滑转 0.47）；现在按行进方向镜像（同一情形滑转 −0.04，和车头朝下坡前进的 −0.04 一致）。倒车时 DP、力矩与 ω 同号。
- **溜车**：最大制动（s = −0.5）也刹不住时，原来照样报"能走"；现在给 `skidding` 标志。
- **水平位移**：车速是沿坡面的，原来直接当水平位移（15° 坡上快 3.4%）；现在乘 cos α。
- **冷启动**：姿态求解不满（关节到极限）时，原来下一步从平地重新解；现在从上一步出发，只在 reset 或出现非有限值时冷启动。
- **NaN**：地形给 NaN 时这一步不动、`kinematics_ok = false`，地形恢复后自动重新解；`std::max` 吞 NaN 的地方都显式处理了。x86-64 上 `(int)NaN` 越界读的入口（取高网格、`h_level`、`W`）都先挡住。
- **参数校验**：`set_soil_params`、`set_geometry` 不合法（K、b、r ≤ 0 等）时报错并保持原参数。
- **出网格**：`off_grid` 标志，GDScript 据此重传网格。

## 车辆物理与线程池测试（Mac，`tests/test_core.cpp`，46 项全部通过；ThreadSanitizer 下也通过）

```
c++ -std=c++17 -O2 -pthread -Wall -Wextra -Icore core/*.cpp tests/test_core.cpp -o /tmp/simtest && /tmp/simtest
```

**检查项**：
- 积分对解析解，误差 < 1e-6；
- 小沉陷极限对小角度精确解，误差 0.05–0.26%；
- 单轮力平衡；
- 软土陷得更深；
- 牵引力随滑转率单调；
- 平地自推进时 DP = 0；
- 运动学：平地、15° 纵坡、10° 横坡、左前轮上 20 cm 台阶，残差都 < 1 mm，差速器方向正确；
- 静力：载荷合计等于车重，纵向力矩平衡；
- 求解器：热启动和冷启动结果相同（1e-8），求值次数更少；
- 倒车、溜车、水平位移 = v·cos α·dt、每步 < 2 ms；
- 健壮性：K = 0、轮宽 0 被拒绝；NaN 地形下不动、恢复后重新解出。

**测试里发现的一件事**：Bekker 教科书上的静沉陷闭式解，把精确积分 B(n+1, ½)/2 近似成了 (3 − n)/3。n = 1.3 时它比精确值低 8.1%。所以测试改成对照精确解，经典式只作参考。

**毅力号的计算结果**：1025 kg、轮径 52.6 cm；轮宽 40 cm 和悬架尺寸是估计值；不计轮刺增益。

| 土 | 静沉陷 | 平地自推进滑转 | 陷车坡度 |
|---|---|---|---|
| M90（风积沙，松散） | 20 mm | 13% | 约 15°（10° 时滑转 47%） |
| GRC-3（松散细砂） | 36 mm | 7% | 约 20°（15° 时滑转 59%） |
| 压实风化层（估计值） | 2.8 mm | — | — |

量级上和火星车在沙地上的经验一致：沙坡超过约 15–20° 就爬不动。GRC-3 虽然陷得更深，但内摩擦角更大（36.7° 对 32°），所以反而更能爬。

## GDScript 用法（编好之后）

```gdscript
var sim := MarsRoverSim.new()
sim.set_soil("M90")
# 高度：快的办法是传一块网格（例：车周围 10 m、5 cm，用 地形LOD.h_cpu 在后台线程采样，车走 3 m 重传一次）
sim.set_height_grid(heights, 200, 200, x0, z0, 0.05)
sim.reset(Vector3(x, 0, z), yaw)
func _physics_process(dt):
	var s := sim.step(dt, wheel_omega, yaw_rate)   # 返回位置、姿态、摇臂和转向架角、车速、滑转、陷车、功率、每个轮子的数据
	rover.position = s.position; …                 # 各轮 sinkage 直接作车辙深度
```

## 已知局限和下一步

1. **几何是估计值**。轮宽、轮距、各枢轴位置都要从 `25042_Perseverance.glb` 量出来（`set_geometry`）。
2. **用真车辙验证**：sol 530 的 Navcam 网格里有真实车辙，量出深度，和各种土的计算沉陷对比，用来选土、校参数。这是这套模型唯一的本地真值。
3. **直接用 C++ 取高**：`h_cpu` 已经在 `MarsTerrainCore` 里（逐位一致）。以后让 `MarsRoverSim` 直接持有它，省掉网格；地编第 2 步的碰撞也用它。
4. **模型还没包含的**：推土阻力、轮刺几何（只有 γg 系数）、转向侧滑、加速度、轮间牵引力对载荷的影响、悬架超出关节极限时的离地重分配。
5. **土壤图**：地类（沙、砾石、基岩、暗岩）→ 土壤参数，每个轮子按自己脚下的地类取土。
